# この本の歩き方

私たちは毎日データベースを使っています。`SELECT` を投げれば結果が返り、`INSERT` したデータはサーバーを再起動しても消えません。あまりに当たり前すぎて、その裏側で何が起きているのかを考える機会はほとんどありません。しかし、その「当たり前」の内側には、コンピュータサイエンスの宝石のような仕組みが詰まっています。ディスクとメモリの速度差を隠蔽するページキャッシュ、数億行から数回のディスクアクセスで目的の行を見つけ出す B-Tree、電源断が起きてもデータを守り抜くジャーナリングと WAL。本書は、それらを**知識として読む**のではなく、**Go で一つずつ実装しながら体で理解する**ための本です。

## なぜ SQLite を教科書にするのか

お手本には SQLite を選びました。理由は 3 つあります。

- **世界で最も使われているデータベースである** — SQLite はすべてのスマートフォン、ブラウザ、無数の組み込み機器に搭載されています。学んだことがそのまま「実世界で最も動いているコード」の理解につながります。
- **構造が驚くほど素直である** — サーバープロセスもネットワーク層もなく、データベース全体がたった 1 つのファイルです。ファイルフォーマットは公式に文書化されており、バイナリエディタで開けば、この本で学ぶ構造がそのまま見えます。
- **アーキテクチャがレイヤーごとに独立している** — トークナイザ → パーサ → 仮想マシン → B-Tree → ページャという層構造がきれいに分かれており、下の層から一段ずつ作っていく本書の構成と完全に一致します。

ただし本書で作るデータベース(以降 **minidb** と呼びます)は、SQLite のファイル形式と完全互換を目指す*のではなく*、その設計思想を踏襲した独自の簡易フォーマットで実装します。完全互換を目指すと、varint エンコーディングやオーバーフローページといった仕様の再現作業に労力の大半を奪われ、「概念を理解する」という本来の目的から外れてしまうからです。その代わり第 3 章では、**本物の SQLite ファイルを Go で書いたパーサでバイナリ解析する**体験を用意しました。読むのは本物、書くのは簡易版 — この組み合わせが、理解の深さと実装の完走しやすさを両立させます。

## 各章の読み方

すべての章は同じリズムで進みます。

1.  **理論** — その章のテーマを、図とともに一般論として理解する
2.  **SQLite ではどうなっているか** — 本物の実装がその理論をどう具体化しているかを見る
3.  **Go で実装する** — minidb に対応する機能を実装する。*コードはすべて完全な形で掲載*しており、写経すればそのまま動きます
4.  **動かして確かめる** — テストや実行結果で動作を検証する

掲載しているコードと実行結果は、すべて実際にコンパイル・実行して検証したものです(検証環境: Go 1.26 / SQLite 3.53)。

## 前提知識

Go の基本文法(構造体、メソッド、スライス、エラー処理、`go test`)を知っていれば読み進められます。データベースの内部構造に関する知識は一切前提としません。ビット演算やバイナリ表現は登場のたびに説明します。
